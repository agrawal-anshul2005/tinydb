# ADR 003: Minimal Artifact Hand-Offs and Context-Window Filtering (D3)

## Status
Accepted

## Context
Passing full conversation histories or dumping entire repository files into every prompt inflates token usage, degrades attention on key constraints, and leaks implementer bias into code review. At the same time, downstream stages need accurate structural facts about TinyDB's modules, acceptance criteria, and baseline test status.

## Decision
We will pass explicit, structured Markdown and JSON artifacts between stages rather than raw chat transcripts, and we will deliberately restrict what each agent sees.

Specifically, Stage 1 receives only the sanitized issue title/body and `skill.md`, outputting `spec.md`. Stage 2 receives `spec.md`, `ARCHITECTURE.md`, and bounded slices from our read-minimal repo tools (`list_dir`, `ast` `repo_map`, `read_file_lines`, `search_symbol`), outputting `design.md` and `context.json`. Stage 3 receives `spec.md`, `design.md`, targeted line ranges of files named in `design.md`, and `status.md`. Stage 4 feeds only failing `pytest` tracebacks back to Stage 3. Crucially, Stage 6 (`ReviewerAgent`) receives **only** the original issue text, the pull request diff (`gh pr diff`), and the repository at the PR HEAD commit; we deliberately exclude `spec.md`, `design.md`, `context.json`, and all implementer/test-loop reasoning traces.

We rejected passing full raw chat histories or whole-repo dumps because they waste free-tier token quotas and contaminate the reviewer with the implementer's self-justifications.

## Consequences
Positive consequences include lower token consumption per run, reproducible debugging (every stage's exact input is saved as an inspectable artifact), and true cognitive isolation for the independent reviewer.

Negative consequences include the risk of information loss if an earlier stage writes an overly terse `spec.md` or `design.md`, which can cause downstream implementation errors.

Neutral consequences include forcing each stage prompt to specify clear output schemas so artifacts remain machine-verifiable and human-readable.
