# ADR 007: PBT-First Hybrid Deterministic and Structured Gate Checks Across All Six Stages (D7)

## Status
Accepted (v2 — supersedes [archive/ADR-007_v1.md](./archive/ADR-007_v1.md))

## Context
Each of the six SDLC stages must pass an explicit check before handing off to the next stage, and must halt with an explanation in its artifact if the check fails. Relying solely on LLM self-assessment invites hallucinations such as non-existent file paths, uncompilable patches, or unverified test claims. Moreover, even when Stage 4 runs automated `pytest` tests, LLM-generated tests that rely purely on hand-picked example inputs frequently overlook edge-case invariants (such as query-cache isolation across arbitrary paths, generator repeatability across arbitrary document orderings, or type-safety across mixed JSON/Python values).

## Decision
We will use deterministic, programmatic checks wherever ground truth exists and restrict LLM-assisted validation strictly to semantic checks, with the deterministic orchestrator (`orchestrator.py`) always making the final pass/fail transition decision — and with **Property-Based Testing (PBT) via `hypothesis` as our primary testing strategy** in Stages 3 and 4:

- **Stage 1 (Requirements):** Structured schema validation verifying unique `FR-*`/`AC-*` IDs, `Given/When/Then` testability checks, zero blocking `[UNRESOLVED]` questions, and explicit `Gate Status: PASS` per `skill.md`.
- **Stage 2 (Design):** Deterministic parser verifying `design.md` names concrete repository file paths (within `tinydb/` or `tests/`) and target function/class symbols cross-checked against our `ast` `repo_map` (or marked as new).
- **Stage 3 (Implementation):** Deterministic `SEARCH/REPLACE` patch verification, non-empty `diff.patch`, `python -m compileall -q tinydb`, and `python -c "import tinydb"`.
- **Stage 4 (Testing — PBT-First Strategy):** `ReproAgent` and Stage 4 enforce a layered testing hierarchy: (1) **Primary — Property-Based Tests (`@given(...)` with `hypothesis`, configured with `settings(max_examples=50, derandomize=True, deadline=None)`)** verifying universal invariants derived from the acceptance criteria (e.g., cache-hit/cache-miss equivalence, idempotency, key conservation, type-safety); (2) **Secondary — Targeted Example-Based Boundary Tests** for explicit error conditions (`KeyError`, `ValueError`, specific regression reproducers); and (3) **Full TinyDB Regression Suite** (`pytest` checked against baseline `status.md`). Stage 4's deterministic check verifies that generated tests include Hypothesis `@given` properties where applicable, every new AC/PBT test passes, and zero baseline regressions occur.
- **Stage 5 (Release):** Deterministic `gh pr view` confirming an open PR and `gh pr checks --watch` confirming `ci.yml` (which also installs `hypothesis` and runs the full `pytest` suite) passes.
- **Stage 6 (Review):** Deterministic round counter (`round <= 2`) plus structured verdict (`APPROVE`, `FIX_CODE`, or `FIX_DESIGN`) parsed from `review.md`.

We rejected example-only testing as the primary strategy because LLMs easily overfit patches to narrow literal examples; we also rejected unbounded randomized fuzzing without `derandomize=True` because flaky non-reproducible CI failures undermine deterministic stage gates.

## Consequences
Positive consequences include much stronger invariant coverage across unexpected edge cases, automatic minimal counterexample shrinking from Hypothesis when feeding `stderr` traces back to `CoderAgent` in Stage 4, and deterministic CI reproducibility via `derandomize=True`.

Negative consequences include slightly longer `pytest` execution times (~1–3 seconds per PBT test, still well under TinyDB's 5-minute budget), requiring `hypothesis` to be installed in `ci.yml`, and the possibility that an LLM writes an overly broad Hypothesis strategy (e.g., generating `NaN` floats where `NaN != NaN`) that triggers a false test failure — mitigated by prompting `ReproAgent` to constrain strategies to valid domain types (e.g., `allow_nan=False`).

Neutral consequences include keeping `hypothesis` strictly inside `tests/` so TinyDB's zero-runtime-dependency architecture remains unaffected.
