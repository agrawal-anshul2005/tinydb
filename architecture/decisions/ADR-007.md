# ADR 007: PBT-First Hybrid Deterministic and Structured Gate Checks Across All Six Stages (D7)

## Status
Accepted (v4 — supersedes [archive/ADR-007_v3.md](./archive/ADR-007_v3.md), [archive/ADR-007_v2.md](./archive/ADR-007_v2.md), and [archive/ADR-007_v1.md](./archive/ADR-007_v1.md))

## Context
Each of the six SDLC stages must pass an explicit check before handing off to the next stage, and must halt with an explanation in its artifact if the check fails. Live runs revealed two concrete gate edge cases: (1) in Run 1 (`44881708823`), Stage 5's unfiltered `gh run list` polled an unrelated `action_required` `pull_request` event instead of our passing `workflow_dispatch` CI run (`44881876871`); and (2) in Run 2 (`44884332705`), `ReproAgent` wrote a syntactically valid PBT test file (`py_compile` passed) using an invalid Hypothesis keyword (`st.recursive(..., max_depth=...)`), which failed `pytest` collection (`rc=2`) and caused all three Coder attempts to fail even though the `tinydb/queries.py` fix was correct.

## Decision
We will enforce hybrid deterministic and structured gates across all six stages, adding a `pytest --collect-only` collection gate (with 1 self-repair attempt) inside Stage 3A (`ReproAgent`) alongside Stage 5's `--event workflow_dispatch` filter:

- **Stage 1 (Requirements):** Structured schema validation verifying unique `FR-*`/`AC-*` IDs, `Given/When/Then` testability, zero blocking `[UNRESOLVED]` questions, and `Gate Status: PASS`.
- **Stage 2 (Design):** Deterministic parser verifying `design.md` names concrete `tinydb/` files and symbols cross-checked against our `ast` `repo_map`.
- **Stage 3 (Implementation):** Stage 3A (`ReproAgent`) verifies both `py_compile` AND `pytest --collect-only` (with 1 self-repair pass on collection error, and lazy imports inside test functions for new symbols); Stage 3B (`CoderAgent`) verifies atomic `SEARCH/REPLACE` patching, non-empty `diff.patch`, `python -m compileall -q tinydb`, and `python -c "import tinydb"`.
- **Stage 4 (Testing — PBT-First):** Layered hierarchy — (1) **Primary:** Hypothesis `@given` PBT invariants (`max_examples=50`, `derandomize=True`, `deadline=None`); (2) **Secondary:** targeted example boundary tests; (3) **Baseline:** full TinyDB regression suite (`status.md`).
- **Stage 5 (Release):** Deterministic `gh pr view` confirming the PR is `OPEN`, explicit `gh workflow run ci.yml --ref <branch>`, and polling `gh run list --workflow ci.yml --branch <branch> --event workflow_dispatch` until `conclusion == success`.
- **Stage 6 (Review):** Deterministic round counter (`round <= 2`) plus structured verdict (`APPROVE`, `FIX_CODE`, or `FIX_DESIGN`) parsed from `review.md`.

## Consequences
Positive consequences include catching hallucinated Hypothesis strategy arguments immediately before Stage 3B coding starts, preventing collection errors from wasting Coder retry budgets, and ensuring flake-free Stage 5 CI verification.

Negative consequences include up to one extra LLM call if `ReproAgent` triggers self-repair on a collection error (still well inside our 15-call per-run budget).

Neutral consequences include preserving a rich, real-run ADR evolution record (`v1 → v2 → v3 → v4`) demonstrating evidence-driven hardening.
