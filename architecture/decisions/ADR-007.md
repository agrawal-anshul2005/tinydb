# ADR 007: PBT-First Hybrid Deterministic and Structured Gate Checks Across All Six Stages (D7)

## Status
Accepted (v3 — supersedes [archive/ADR-007_v2.md](./archive/ADR-007_v2.md) and [archive/ADR-007_v1.md](./archive/ADR-007_v1.md))

## Context
Each of the six SDLC stages must pass an explicit check before handing off to the next stage, and must halt with an explanation in its artifact if the check fails. In v2, we adopted Property-Based Testing (`hypothesis`) as our primary Stage 3/4 testing strategy. During our first live GitHub Actions run on Issue #1 (`44881708823`), Stages 1–4 passed on Attempt 1 and our dispatched `ci.yml` run (`44881876871`) succeeded, but Stage 5's `gh run list --workflow ci.yml --branch <branch>` lacked an `--event workflow_dispatch` filter and erroneously polled a `pull_request` event run (`44881878178`, `conclusion=action_required`).

## Decision
We will retain the PBT-first hybrid deterministic checks from v2 across all six stages, and harden Stage 5's CI gate to filter exclusively on `--event workflow_dispatch`:

- **Stage 1 (Requirements):** Structured schema validation verifying unique `FR-*`/`AC-*` IDs, `Given/When/Then` testability, zero blocking `[UNRESOLVED]` questions, and `Gate Status: PASS`.
- **Stage 2 (Design):** Deterministic parser verifying `design.md` names concrete `tinydb/` files and symbols cross-checked against our `ast` `repo_map`.
- **Stage 3 (Implementation):** Deterministic `SEARCH/REPLACE` patch verification, non-empty `diff.patch`, `python -m compileall -q tinydb`, and `python -c "import tinydb"`.
- **Stage 4 (Testing — PBT-First):** Layered hierarchy — (1) **Primary:** Hypothesis `@given` PBT invariants (`max_examples=50`, `derandomize=True`, `deadline=None`); (2) **Secondary:** targeted example boundary tests; (3) **Baseline:** full TinyDB regression suite (`status.md`).
- **Stage 5 (Release):** Deterministic `gh pr view` confirming the PR is `OPEN`, explicit `gh workflow run ci.yml --ref <branch>`, and polling `gh run list --workflow ci.yml --branch <branch> --event workflow_dispatch` until `conclusion == success`.
- **Stage 6 (Review):** Deterministic round counter (`round <= 2`) plus structured verdict (`APPROVE`, `FIX_CODE`, or `FIX_DESIGN`) parsed from `review.md`.

## Consequences
Positive consequences include deterministic, flake-free Stage 5 CI verification unaffected by `pull_request` fork-approval noise, alongside rigorous Hypothesis PBT invariant verification in Stage 4.

Negative consequences include requiring `actions: write` on the builder job to dispatch `ci.yml` and keeping `hypothesis` installed in `ci.yml`.

Neutral consequences include preserving full traceability of how Run 1 empirically uncovered and fixed an edge case in GitHub Actions event filtering.
