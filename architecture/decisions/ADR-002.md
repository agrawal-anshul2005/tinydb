# ADR 002: Deterministic Orchestrator with Symmetric Bounded Feedback Loops Across Two Jobs (D2)

## Status
Accepted (v4 — supersedes [archive/ADR-002_v3.md](./archive/ADR-002_v3.md), [archive/ADR-002_v2.md](./archive/ADR-002_v2.md), and [archive/ADR-002_v1.md](./archive/ADR-002_v1.md))

## Context
The workflow must strictly enforce six stage gates, allow failing tests in Stage 4 to route back to Stage 3, allow reviewer change requests in Stage 6 to route back to either Stage 2 (approach/design flaws) or Stage 3 (code defects) for at most two review rounds, and prevent runaway agent loops. Live runs `44884332705` and `44885745409` further demonstrated that Property-Based Testing (`hypothesis`) generation in Stage 3A (`ReproAgent`) can occasionally produce invalid strategy calls or health-check failures that cannot be fixed by `CoderAgent` alone unless `ReproAgent` also runs inside a bounded self-correcting loop.

## Decision
We will control Stages 1 through 5 with a deterministic Python orchestrator (`workflow/agents/orchestrator.py`) inside a builder GitHub Actions job (`sdlc_pipeline`), and execute Stage 6 (`ReviewerAgent`) in a separate downstream GitHub Actions job (`independent_review`).

Inside Stage 3/4, we apply **symmetric bounded Evaluator-Optimizer loops** with deterministic preprocessing and tiered model escalation:
1. **`ReproAgent` (Stage 3A PBT Test Generation):** First applies deterministic AST/regex auto-corrections (`_harden_hypothesis_settings`: `Query()[field]`, bounded ASCII field-name strategies, `suppress_health_check=list(HealthCheck)`). If static linting, `pytest --collect-only`, or runtime Hypothesis harness checks still fail, the orchestrator loops `ReproAgent` for up to **2 attempts on `gemini-3.5-flash` followed by 1 escalated attempt on `gemini-3.7-flash`** (`MAX_REPRO_ATTEMPTS=3`).
2. **`CoderAgent` (Stage 3B/4 Implementation & Testing):** Feeds failing `pytest` / shrunk Hypothesis counterexample `stderr` back to `CoderAgent` for up to **2 attempts on `gemini-3.5-flash` followed by 1 escalated attempt on `gemini-3.7-flash`** (`MAX_CODER_ATTEMPTS=3`).

Across Stages 5 and 6, `.github/workflows/autose.yml` wires bounded round jobs (Round 1 and, only if changes are requested, Round 2): a `FIX_DESIGN` verdict re-enters at Stage 2, a `FIX_CODE` verdict re-enters at Stage 3, and an `APPROVE` verdict or exhaustion of Round 2 halts cleanly for human decision. Transient `429`/`503` provider errors do not count against any iteration limit (ADR-009 v2).

We rejected an LLM-driven planner/router and an unbounded single-job loop because they cannot guarantee stage-gate enforcement or OS-level job isolation for the reviewer.

## Consequences
Positive consequences include guaranteed execution of all six stage gates, symmetric resilience for both PBT test authoring and code patching, predictable worst-case iteration bounds, and hard enforcement of the two-round review ceiling.

Negative consequences include slightly more YAML/orchestrator boilerplate and up to 2 extra LLM calls on runs where `ReproAgent` requires self-repair.

Neutral consequences include deterministic fail-closed halting: if either `ReproAgent` or `CoderAgent` exhausts its 3 attempts, the run halts with a full attempt table in `status.md` / `test_report.md` for human inspection.
