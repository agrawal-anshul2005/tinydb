# ADR 005: Context-Saving Local AST Tools, Diff-Based Editing, Hypothesis PBT, and Least-Privilege `gh` CLI (D5)

## Status
Accepted (v2 — supersedes [archive/ADR-005_v1.md](./archive/ADR-005_v1.md))

## Context
Coding agents must inspect TinyDB's code, apply edits accurately, verify behavioral invariants rigorously, and interact with GitHub issues and pull requests without over-privileged credentials or bloated runtime dependencies. Rewriting entire source files from scratch causes syntax hallucinations and wastes tokens, while installing heavy native tooling such as Tree-sitter grammars or running an external MCP server inside ephemeral GitHub Actions runners introduces build fragility. Furthermore, standard example-only unit tests written by LLMs often test only happy-path inputs copied verbatim from the issue description, missing edge-case invariant failures.

## Decision
We will provide each agent with a minimal, least-privilege toolset composed of: (1) lightweight pure-Python repository navigation tools in `workflow/agents/tools.py` — `list_directory`, `repo_map` (built with Python's standard-library `ast` module to emit class/function signatures and line numbers), `read_file_lines` (targeted line slices), and `search_symbol` (`git grep` / regex); (2) a `SEARCH/REPLACE` diff-based patch applicator for `CoderAgent` instead of whole-file rewrites; (3) local `pytest`, **`hypothesis` (strictly dev/test-only for Property-Based Testing — never imported in `tinydb/` runtime code)**, and `compileall` subprocess execution; and (4) the pre-installed GitHub CLI (`gh`) authenticated with each job's scoped `GITHUB_TOKEN`.

We rejected a separate GitHub MCP server because GitHub Actions runners already ship with `gh`, which inherits each job's exact least-privilege `GITHUB_TOKEN` permissions (`contents: read` for Stage 6 versus `contents: write` for Stage 5). We rejected Tree-sitter in favor of Python's built-in `ast` module because TinyDB is 100% Python, giving identical structural skeletons with zero native build dependencies. We added `hypothesis` exclusively to the test environment so TinyDB's zero-runtime-dependency constraint (`ARCHITECTURE.md`) remains strictly untouched.

## Consequences
Positive consequences include dramatically lower token consumption during exploration and editing, fewer syntax regressions from `SEARCH/REPLACE` patches, systematic invariant falsification via `hypothesis` shrinking, zero third-party runtime dependencies in `tinydb/`, and platform-enforced least privilege between jobs.

Negative consequences include `SEARCH/REPLACE` blocks occasionally failing to match if the LLM hallucinates whitespace (mitigated by strict verification and retry feedback), adding `hypothesis` to CI test setup (`ci.yml` and `autose.yml`), and the need to bound Hypothesis example counts (`max_examples=50`, `derandomize=True`) so tests remain fast and reproducible.

Neutral consequences include straightforward extensibility: if ported to a multi-language repository later, `repo_map` can swap `ast` for Tree-sitter behind the same tool interface.
