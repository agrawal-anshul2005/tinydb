# ADR 004: GitHub Artifacts, Dedicated Feature Branches, and Restart Semantics (D4)

## Status
Accepted

## Context
An automated SDLC pipeline spans multiple stages and separate GitHub Actions jobs (including up to two review rounds) and must remain auditable by maintainers after a run completes. State must survive job boundaries (Builder Job → Review Job → optional Round 2 Builder Job) without polluting the protected `main` branch or leaving orphaned temporary files in the pull request diff.

## Decision
We will split persistent state cleanly across three GitHub-native mechanisms: code and test changes live on a deterministic per-issue feature branch (`autose/issue-<N>`); stage outputs (`spec.md`, `design.md`, `context.json`, `status.md`, `diff.patch`, `test_report.md`, `pr.md`, `review.md`, `usage.json`) are stored via GitHub Actions artifacts (`actions/upload-artifact@v4` / `actions/download-artifact@v4`); and pull request metadata plus review verdicts live on the GitHub Pull Request itself.

We rejected committing intermediate artifacts (`spec.md`, `design.md`, `context.json`) onto the PR branch because they would clutter the production diff reviewed by humans and by Stage 6. We also rejected GitHub Actions cache (`actions/cache`) because caches are evictable and not cleanly inspectable per run.

If a workflow run is restarted for the same issue, Stage 3 checks whether `autose/issue-<N>` already exists (resetting cleanly from `main` on a fresh run, or checking out the existing PR branch on Round 2 revision), and Stage 5 updates an existing open PR rather than creating duplicates.

## Consequences
Positive consequences include clean production PR diffs containing only source and test changes, permanent 90-day audit trails of every stage artifact per GitHub Actions run, and idempotent restarts without duplicate PRs.

Negative consequences include needing explicit `actions/download-artifact` steps between Round 1 and Round 2 jobs and ensuring temporary working files are cleaned or ignored before `git add` in Stage 5.

Neutral consequences include relying on GitHub's artifact retention window for long-term inspection while archiving final run links and CSV summaries in `results/`.
