# ADR 002 (v2): Deterministic Orchestrator with Bounded Feedback Loops Across Two Jobs (D2)

## Status
Superseded by active [ADR-002.md](../ADR-002.md) (v3) — superseded after live API probing showed `gemini-3.8-flash` returning `503 UNAVAILABLE` high-demand errors; escalation switched to `gemini-3.5-flash` (×2) → `gemini-3.7-flash` (×1) with an automatic fallback chain.

## Context
Following the deprecation of Gemini 2.5 models (`ADR-006_v1.md`), the Evaluator-Optimizer escalation loop needed to reference active Gemini 3.x models while preserving deterministic gate enforcement, bounded retries, and two-job reviewer isolation.

## Decision
We will retain the deterministic Python orchestrator (`workflow/agents/orchestrator.py`) for Stages 1–5 and the isolated `independent_review` job for Stage 6, updating the Stage 3/4 Evaluator-Optimizer loop to run up to 2 attempts on `gemini-3.5-flash-lite` followed by 1 escalated attempt on `gemini-3.8-flash` (3 total attempts per round).

## Consequences
Positive consequences include eliminating deprecated Gemini 2.5 model identifiers while keeping bounded loop guarantees intact.

Negative consequences (discovered immediately upon live API probing) include `gemini-3.8-flash` experiencing `503 UNAVAILABLE` spikes on the free tier, which necessitated adding a verified escalation target (`gemini-3.7-flash`) and automatic `429`/`503` fallback chain in v3.
