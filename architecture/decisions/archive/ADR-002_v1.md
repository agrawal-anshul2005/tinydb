# ADR 002 (v1): Deterministic Orchestrator with Bounded Feedback Loops Across Two Jobs (D2)

## Status
Superseded by [archive/ADR-002_v2.md](./ADR-002_v2.md) and active [ADR-002.md](../ADR-002.md) (v3) — superseded when the Evaluator-Optimizer escalation models migrated from deprecated Gemini 2.5 to verified Gemini 3.x models.

## Context
The workflow must strictly enforce six stage gates, allow failing tests in Stage 4 to route back to Stage 3, allow reviewer change requests in Stage 6 to route back to either Stage 2 (approach/design flaws) or Stage 3 (code defects) for at most two review rounds, and prevent runaway agent loops. Letting an LLM orchestrator decide arbitrary transitions risks non-deterministic stage skipping, infinite retries, and unexpected API quota exhaustion.

## Decision
We will control Stages 1 through 5 with a deterministic Python orchestrator (`workflow/agents/orchestrator.py`) inside a builder GitHub Actions job (`sdlc_pipeline`), and execute Stage 6 (`ReviewerAgent`) in a separate downstream GitHub Actions job (`independent_review`).

Inside Stages 3 and 4, the orchestrator runs an Evaluator-Optimizer loop that feeds failing `pytest` `stderr` traces back to `CoderAgent` for up to 2 attempts on `gemini-2.5-flash` followed by 1 escalated attempt on `gemini-2.5-pro` (3 total attempts per round). Across Stages 5 and 6, `.github/workflows/autose.yml` wires bounded round jobs (Round 1 and, only if changes are requested, Round 2): a `FIX_DESIGN` verdict re-enters at Stage 2, a `FIX_CODE` verdict re-enters at Stage 3, and an `APPROVE` verdict or exhaustion of Round 2 halts cleanly for human decision.

We rejected an LLM-driven planner/router and an unbounded single-job loop because they cannot guarantee stage-gate enforcement or OS-level job isolation for the reviewer.

## Consequences
Positive consequences include guaranteed execution of all six stage gates, predictable worst-case API call bounds, clear visual progress in the GitHub Actions job graph, and hard enforcement of the two-round review ceiling.

Negative consequences include somewhat verbose YAML wiring to express Round 1 and Round 2 across separate builder and reviewer jobs, and reliance on Gemini 2.5 models later found to be deprecated.
