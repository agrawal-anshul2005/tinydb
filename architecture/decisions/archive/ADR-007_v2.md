# ADR 007 (v2): PBT-First Hybrid Deterministic and Structured Gate Checks Across All Six Stages (D7)

## Status
Superseded by active [ADR-007.md](../ADR-007.md) (v3) — superseded after Run 1 on Issue #1 (`44881708823`) showed that Stage 5's `gh run list --workflow ci.yml --branch <branch>` picked up a bot-PR `pull_request` event (`conclusion=action_required`) instead of the passing `workflow_dispatch` CI run (`44881876871`, `conclusion=success`); v3 filters Stage 5's CI gate explicitly by `--event workflow_dispatch`.

## Context
Stages 1–6 require deterministic checks wherever ground truth exists and Property-Based Testing (PBT) via `hypothesis` as the primary Stage 3/4 testing strategy.

## Decision
We enforced schema/testability checks in Stage 1, AST file/symbol checks in Stage 2, `compileall`/import checks in Stage 3, Hypothesis PBT (`max_examples=50`, `derandomize=True`) + boundary + full regression checks in Stage 4, PR-open + `ci.yml` check in Stage 5, and bounded round/verdict checks in Stage 6.

## Consequences
Stages 1–4 worked on the first try (generating 4 Hypothesis PBTs + 3 boundary tests and passing full regression on Attempt 1), but Stage 5's unfiltered `gh run list` misread an unrelated `action_required` `pull_request` run as a CI failure despite `workflow_dispatch` run `44881876871` succeeding. Fixed in v3.
