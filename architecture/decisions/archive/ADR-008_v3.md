# ADR 008 (v3): Job-Isolated, Fresh-Context, Cross-Family Reviewer Independence (D8)

## Status
Superseded by active [ADR-008.md](../ADR-008.md) (v4) — superseded when adding Groq failover (`ADR-006` v6) revealed that overlapping fallback lists (`gemma-4-*`, `gemini-3.7-flash`, or shared Groq models) could theoretically allow Stages 1–5 and Stage 6 to execute on the same model during a `503` cascade; v4 enforces mathematically disjoint primary + fallback pools (`BuilderSet ∩ ReviewerSet = ∅`) with a runtime assertion in `stage6_review.py`.

## Context
After Run 4 revealed GitHub Models was retired, we moved Stage 6 to open-weight Gemma 4 (`gemma-4-31b-it` / `gemma-4-26b-a4b-it`) while keeping Gemini 3.x for Stages 1–4.

## Decision
We ran Stage 6 in an isolated read-only job using Gemma 4 primary with fallback to `gemini-3.7-flash`/`3.6-flash`, while Stages 1–5 also included Gemma 4 in their fallback chains.

## Consequences
Normal runs had cross-family independence, but under heavy `503` failovers both builder and reviewer could land on the same fallback model; v4 eliminates all overlap across primary and fallback pools and asserts disjointness at runtime.
