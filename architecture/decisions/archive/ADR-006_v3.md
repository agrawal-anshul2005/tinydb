# ADR 006 (v3): Multi-Provider Free-Tier Model Allocation (Gemini 3.x + GitHub Models) (D6)

## Status
Superseded by active [ADR-006.md](../ADR-006.md) (v4) — superseded after Run 1 on Issue #1 (`44881708823`) revealed that on a forked repository, the default `GITHUB_TOKEN` returned an empty body from `models.github.ai/inference/chat/completions`; v4 switches GitHub Models authentication to a dedicated `GH_MODELS_TOKEN` repository secret (fine-grained PAT with `models: read`) plus explicit `X-GitHub-Api-Version: 2022-11-28` header.

## Context
Our agentic SDLC workflow runs across six stages and bounded retry loops for five evaluation issues under a strict zero-cost constraint. Live endpoint probing against our free-tier Gemini key showed `gemini-4-argon` and `gemini-4-neon` returning `429 RESOURCE_EXHAUSTED` and `gemini-3.8-flash` returning `503 UNAVAILABLE`, while `gemini-3.5-flash-lite`, `gemini-3.5-flash`, `gemini-3.6-flash`, `gemini-3.7-flash`, and `gemma-4-31b-it` returned `200 OK`.

## Decision
We used a zero-LLM deterministic orchestrator (`orchestrator.py`), Gemini 3.x (`gemini-3.5-flash-lite` for Stages 1–2, `gemini-3.5-flash` ×2 → `gemini-3.7-flash` ×1 for Stages 3–4), and GitHub Models (`openai/gpt-4o-mini` for Stage 5, `openai/gpt-4o` for Stage 6) authenticated via default `GITHUB_TOKEN`.

## Consequences
Stages 1–4 succeeded on Attempt 1 on Issue #1, but Stage 5's GitHub Models call using default `GITHUB_TOKEN` returned empty responses on our forked repository, motivating v4's `GH_MODELS_TOKEN` secret.
