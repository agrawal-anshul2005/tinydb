# ADR 002 (v3): Deterministic Orchestrator with Bounded Feedback Loops Across Two Jobs (D2)

## Status
Superseded by active [ADR-002.md](../ADR-002.md) (v4) — superseded after Run 2 (`44884332705`) and Run 3 (`44885745409`) showed that improper Hypothesis PBT tests need the same bounded Evaluator-Optimizer + model-escalation loop as `CoderAgent`; v4 makes both `ReproAgent` (PBT test generation) and `CoderAgent` symmetric 2-primary + 1-escalated loops after deterministic auto-sanitization.

## Context
The workflow must strictly enforce six stage gates, allow failing tests in Stage 4 to route back to Stage 3, allow reviewer change requests in Stage 6 to route back to either Stage 2 or Stage 3 for at most two review rounds, and prevent runaway agent loops.

## Decision
We controlled Stages 1–5 via a deterministic Python orchestrator (`orchestrator.py`) with a bounded 2×`gemini-3.5-flash` + 1×`gemini-3.7-flash` Evaluator-Optimizer loop for `CoderAgent`, and executed Stage 6 in an isolated GitHub Actions job (`independent_review`) capped at 2 review rounds.

## Consequences
`CoderAgent` retries worked cleanly, but single-shot `ReproAgent` test-generation mistakes (invalid Hypothesis kwargs / `FailedHealthCheck`) cascaded into all 3 Coder attempts; v4 adds a symmetric bounded loop with deterministic sanitization + model escalation to `ReproAgent`.
