# ADR 009 (v1): Budgets, Timeouts, Sandboxed Execution, and Prompt-Injection Defenses (D9)

## Status
Superseded by active [ADR-009.md](../ADR-009.md) (v2) — superseded to explicitly decouple transient provider availability errors (HTTP `429`, `503`, `500`, `502`, `504`) from per-run call/token budgets and stage retry caps, logging them separately as `transient_errors_uncounted` in `usage.json`.

## Context
GitHub Actions workflows triggered by issues and comments operate on untrusted natural-language input and invoke external LLM APIs plus code execution (`pytest`).

## Decision
We enforced untrusted-input delimiter isolation, allowlisted writes (`tinydb/`, `tests/`), hard caps (`MAX_TOKENS_PER_RUN=200000`, `MAX_LLM_CALLS_PER_RUN=15`, `MAX_CODER_ATTEMPTS=3`, `MAX_REVIEW_ROUNDS=2`), job timeouts (`15`/`10` min), and ephemeral VM execution.

## Consequences
Live runs `44884332705` and `44885745409` showed frequent transient `503 UNAVAILABLE` demand spikes on free-tier Gemini; v2 explicitly formalizes that transient provider failures never count against call/token/retry limits and bumps `MAX_LLM_CALLS_PER_RUN` to `20` to accommodate symmetric `ReproAgent` + `CoderAgent` loops.
