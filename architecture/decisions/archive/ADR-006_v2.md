# ADR 006 (v2): Multi-Provider Free-Tier Model Allocation (Gemini 3.x + GitHub Models) (D6)

## Status
Superseded by active [ADR-006.md](../ADR-006.md) (v3) — superseded after live probing against our Free-Tier Gemini API key returned `503 UNAVAILABLE` for `gemini-3.8-flash` and `429 RESOURCE_EXHAUSTED` for `gemini-4-argon`/`gemini-4-neon`, while `gemini-3.5-flash`, `gemini-3.6-flash`, `gemini-3.7-flash`, and `gemma-4-31b-it` returned `200 OK`.

## Context
After deprecating `ADR-006_v1.md` due to Gemini 2.5 deprecation and single-provider quota pressure, we listed live models on our Gemini API key and evaluated free alternatives (rejecting desktop Ollama on a self-hosted runner due to public-repo security risks and loss of ephemeral VM sandboxing). GitHub Actions' built-in GitHub Models (`models: read` via `GITHUB_TOKEN`) provides a separate free inference pool with zero extra secrets.

## Decision
We will combine a zero-LLM deterministic Python orchestrator (`orchestrator.py`) with a multi-provider free-tier split: `gemini-3.5-flash-lite` (fallback `gemma-4-31b-it`) for Stages 1–4 primary attempts, `gemini-3.8-flash` for Stage 3/4 escalation, GitHub Models `openai/gpt-4o-mini` for Stage 5 Delivery, and GitHub Models `openai/gpt-4o` (fallback `meta/llama-3.3-70b-instruct`) for Stage 6 Independent Review.

## Consequences
Positive consequences include eliminating deprecated Gemini 2.5 models, offloading Stages 5–6 off the Gemini quota pool, and achieving true cross-provider reviewer independence.

Negative consequences (discovered via live 5-second smoke-test probing before coding) include `gemini-3.8-flash` failing with `503 UNAVAILABLE` demand spikes, proving that an empirically verified escalation model (`gemini-3.7-flash`) and ordered fallback chain were required in v3.
