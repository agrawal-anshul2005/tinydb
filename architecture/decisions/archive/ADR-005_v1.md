# ADR 005 (v1): Context-Saving Local AST Tools, Diff-Based Editing, and Least-Privilege `gh` CLI (D5)

## Status
Superseded by active [ADR-005.md](../ADR-005.md) (v2) — superseded to add `hypothesis` (dev/test-only) to the local testing toolset to support Property-Based Testing (PBT) as our primary Stage 3/4 testing strategy.

## Context
Coding agents must inspect TinyDB's code, apply edits accurately, run `pytest`, and interact with GitHub issues and pull requests without over-privileged credentials or bloated tool dependencies. Rewriting entire source files from scratch causes syntax hallucinations and wastes tokens, while installing heavy native tooling such as Tree-sitter grammars or running an external MCP server inside ephemeral GitHub Actions runners introduces build fragility and unnecessary setup latency.

## Decision
We will provide each agent with a minimal, least-privilege toolset composed of: (1) lightweight pure-Python repository navigation tools in `workflow/agents/tools.py` — `list_directory`, `repo_map` (built with Python's standard-library `ast` module to emit class/function signatures and line numbers), `read_file_lines` (targeted line slices), and `search_symbol` (`git grep` / regex); (2) a `SEARCH/REPLACE` diff-based patch applicator for `CoderAgent` instead of whole-file rewrites; (3) local `pytest` and `compileall` subprocess execution; and (4) the pre-installed GitHub CLI (`gh`) authenticated with each job's scoped `GITHUB_TOKEN`.

We rejected a separate GitHub MCP server because GitHub Actions runners already ship with `gh`, and `gh` naturally inherits each job's exact least-privilege `GITHUB_TOKEN` permissions (`contents: read` for Stage 6 versus `contents: write` for Stage 5). We rejected Tree-sitter in favor of Python's built-in `ast` module because TinyDB is 100% Python, giving identical structural skeletons with zero native build dependencies.

## Consequences
Positive consequences include dramatically lower token consumption during exploration and editing, fewer syntax regressions from `SEARCH/REPLACE` patches, zero third-party binary build failures on CI runners, and OS/token-enforced least privilege between jobs.

Negative consequences include relying solely on example-based `pytest` assertions, which can miss subtle invariant violations across unexpected input combinations; v2 adds `hypothesis` as a dev-only PBT tool.
