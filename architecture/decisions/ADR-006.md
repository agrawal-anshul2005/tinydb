# ADR 006: Cross-Family Free-Tier Model Allocation with Groq Cross-Provider Failover (D6)

## Status
Accepted (v6 — supersedes [archive/ADR-006_v5.md](./archive/ADR-006_v5.md), [archive/ADR-006_v4.md](./archive/ADR-006_v4.md), [archive/ADR-006_v3.md](./archive/ADR-006_v3.md), [archive/ADR-006_v2.md](./archive/ADR-006_v2.md), and [archive/ADR-006_v1.md](./archive/ADR-006_v1.md))

## Context
Although v5 (Gemini 3.x + open-weight Gemma 4 on Google AI Studio) completed all six stages on Issue #1 (PR #8, 3/3 hidden tests passed, line-cited `APPROVE` from `gemma-4-26b-a4b-it`), subsequent probing and Issue #2 exposed single-provider availability limits under our \$0 free-tier cap: (1) `antigravity-preview-latest` and `antigravity-preview-09-2026` returned `400 INVALID_ARGUMENT` (Interactions API only, incompatible with `generate_content`); (2) simultaneous `503 UNAVAILABLE` spikes occasionally hit `gemini-3.7-flash`, `gemini-3.6-flash`, and `gemma-4-26b-a4b-it`; and (3) `gemma-4-31b-it` enforces a `16,000` free-tier input-TPM ceiling. Relying on a single cloud host risks intermittent CI aborts during peak demand waves.

## Decision
We will retain our **zero-LLM deterministic orchestrator** and **Gemini 3.x + Gemma 4** primary allocation (with `gemma-4-26b-a4b-it` prioritized ahead of `gemma-4-31b-it` and `CoderAgent` prompts trimmed well below 16k input tokens), and add **Groq Free Developer Tier** (`https://api.groq.com/openai/v1/chat/completions`, authenticated via repository secret `GROQ_API_KEY`, \$0 cost, ~30 RPM / ~1,000 RPD) as an **automatic cross-provider last-resort fallback** in `llm.py`:

1. **Orchestrator (`orchestrator.py`):** **Deterministic Python (no LLM).**
2. **Stages 1–2 (`RequirementsAgent`, `ExplorerDesignAgent`):** `gemini-3.5-flash-lite` → `gemini-3.5-flash` → `gemma-4-31b-it` → **Groq failover**.
3. **Stage 3/4 Primary (`ReproAgent`, `CoderAgent` attempts 1–2):** `gemini-3.5-flash-lite` → `gemini-3.5-flash` → `gemma-4-26b-a4b-it` → **Groq failover**.
4. **Stage 3/4 Escalation (`ReproAgent` / `CoderAgent` attempt 3):** `gemini-3.7-flash` → `gemini-3.6-flash` → `gemini-3.5-flash-lite` → `gemma-4-26b-a4b-it` → **Groq failover**.
5. **Stage 5 (`DeliveryAgent`) & Stage 6 (`ReviewerAgent`):** `gemma-4-26b-a4b-it` → `gemma-4-31b-it` → (`gemini-3.7-flash` / `3.6-flash` for Stage 6) → **Groq failover**.
6. **Groq Last-Resort Chain (`GROQ_FALLBACK_MODELS`):** `llama-3.3-70b-versatile` → `openai/gpt-oss-120b` → `llama-3.1-8b-instant` (pure stdlib `urllib.request`, zero extra pip dependencies).

We rejected `antigravity-preview-*` (`400` Interactions API only), retired GitHub Models (`models.github.ai`), paid providers, and self-hosted laptop runners.

## Consequences
Positive consequences include eliminating single-provider `503`/`429` outages while maintaining a strict \$0 cap, zero new Python package dependencies (pure `urllib.request`), faster failover (`4s` retry on `503`), and genuine cross-provider backup (Meta Llama 3.3 70B / OpenAI GPT-OSS 120B on Groq) whenever Google AI Studio spikes.

Negative consequences include configuring a second free-tier repository secret (`GROQ_API_KEY`) and slight cross-provider prompt formatting differences if Groq triggers mid-run.

Neutral consequences include transparent attribution in `usage.json` / `review_usage.json` logging `provider: "groq"` and `fallback_used: true` whenever last-resort failover occurs.
