# ADR 006: Cross-Family Free-Tier Model Allocation (Gemini 3.x + Open-Weight Gemma 4) (D6)

## Status
Accepted (v5 — supersedes [archive/ADR-006_v4.md](./archive/ADR-006_v4.md), [archive/ADR-006_v3.md](./archive/ADR-006_v3.md), [archive/ADR-006_v2.md](./archive/ADR-006_v2.md), and [archive/ADR-006_v1.md](./archive/ADR-006_v1.md))

## Context
Across four live iterations, empirical evidence narrowed our zero-cost model selection: (1) Gemini 2.5 is deprecated; (2) live probing ruled out `gemini-4-*` (`429`) and `gemini-3.8-flash` (`503`), while `gemini-3.5-flash-lite` showed higher stability than `gemini-3.5-flash` during live demand spikes; and (3) Run 4 on Issue #1 (CI `44888636577`) confirmed that `models.github.ai/inference/chat/completions` returned non-JSON HTML (`Expecting value: line 1 column 1`) even with a dedicated PAT (`GH_MODELS_TOKEN`) because the standalone GitHub Models inference service has been retired. Meanwhile, Google AI Studio's open-weight **Gemma 4** models (`gemma-4-31b-it` and `gemma-4-26b-a4b-it`) responded `200 OK` on our free-tier key with a separate, generous daily RPD pool and represent an independent model family distinct from proprietary Gemini 3.x.

## Decision
We will standardize on a **cross-family free-tier allocation** on `google-genai` (`GEMINI_API_KEY`) paired with our **zero-LLM deterministic orchestrator**, with ordered `429`/`503` fallback chains:

1. **Orchestrator (`orchestrator.py`):** **Deterministic Python (no LLM).**
2. **Stages 1–2 (`RequirementsAgent`, `ExplorerDesignAgent`):** **`gemini-3.5-flash-lite`** (fallback: `gemini-3.5-flash` → `gemma-4-31b-it`).
3. **Stage 3/4 Primary (`ReproAgent`, `CoderAgent` attempts 1–2):** **`gemini-3.5-flash-lite`** first (to minimize `503` backoff latency observed on `gemini-3.5-flash` in Run 4) with fallback to `gemini-3.5-flash` → `gemma-4-31b-it`.
4. **Stage 3/4 Escalation (`ReproAgent` / `CoderAgent` attempt 3):** **`gemini-3.7-flash`** (fallback: `gemini-3.6-flash` → `gemma-4-31b-it`).
5. **Stage 5 (`DeliveryAgent`):** Open-weight **`gemma-4-31b-it`** (fallback: `gemma-4-26b-a4b-it` → `gemini-3.5-flash-lite`), conserving Gemini Flash RPD for coding.
6. **Stage 6 (`ReviewerAgent`):** Open-weight **`gemma-4-31b-it`** (fallback: `gemma-4-26b-a4b-it` → `gemini-3.7-flash` → `gemini-3.6-flash`). Using an open-weight 31B Gemma 4 model to review code written by proprietary Gemini 3.5 Flash preserves **cross-architecture model diversity** while eliminating the retired GitHub Models dependency.

We rejected continuing with GitHub Models (`models.github.ai` retired), paid direct-billed providers (violate \$0 budget), and desktop Ollama on a self-hosted runner (public-repo security risk).

## Consequences
Positive consequences include 100% live availability under our \$0 free-tier cap, single-secret operational simplicity (`GEMINI_API_KEY` only — `GH_MODELS_TOKEN` can be revoked immediately), faster Stage 3/4 runs by prioritizing stable `gemini-3.5-flash-lite`, separate high-RPD Gemma 4 headroom for Stages 5–6, and true cross-architecture diversity between implementer (Gemini 3.5) and reviewer (Gemma 4 31B).

Negative consequences include remaining on a single API host (Google AI Studio) and accepting Google AI Studio's free-tier data-use terms (acceptable for public MIT-licensed TinyDB).

Neutral consequences include logging exact model ID, fallback status, token counts, and uncounted transient errors in `usage.json` and `review_usage.json`.
