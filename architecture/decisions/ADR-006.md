# ADR 006: Multi-Provider Free-Tier Model Allocation (Gemini 3.x + GitHub Models) (D6)

## Status
Accepted (v3 — supersedes [archive/ADR-006_v2.md](./archive/ADR-006_v2.md) and [archive/ADR-006_v1.md](./archive/ADR-006_v1.md))

## Context
Our agentic SDLC workflow runs across six stages and bounded retry loops for five evaluation issues under a strict zero-cost constraint. On Google AI Studio's Free Tier (automatic \$0 spending cap, no billing account attached), Gemini 2.5 models are deprecated (rerouting effective December 1, 2026) and live endpoint probing against our free-tier key revealed sharp availability differences across newer models: `gemini-4-argon` and `gemini-4-neon` returned `429 RESOURCE_EXHAUSTED` (no free-tier quota), and `gemini-3.8-flash` returned `503 UNAVAILABLE` due to high-demand throttling. In contrast, `gemini-3.5-flash-lite`, `gemini-3.5-flash`, `gemini-3.6-flash`, `gemini-3.7-flash`, and open-weight `gemma-4-31b-it` all responded cleanly. Relying on a single unstable model risks stalled runs, and using the same model family for both coding and reviewing weakens independent defect detection.

## Decision
We will use an empirically verified **multi-provider free-tier allocation** paired with a **zero-LLM deterministic orchestrator** and an automatic `429`/`503` fallback chain, with all model IDs parameterized via workflow environment variables:

1. **Orchestrator (`orchestrator.py`):** **Deterministic Python (no LLM).** Gate enforcement, retry counting, token budgeting, and path allowlisting require zero LLM calls and eliminate non-deterministic stage skipping.
2. **Stages 1–2 (`RequirementsAgent`, `ExplorerDesignAgent`):** **`gemini-3.5-flash-lite`** (fallback chain: `gemini-3.5-flash` → `gemma-4-31b-it`) via `google-genai` (`GEMINI_API_KEY`). Structured specification and AST-assisted design run quickly within high free-tier RPD limits.
3. **Stage 3/4 Primary (`ReproAgent`, `CoderAgent` attempts 1–2):** **`gemini-3.5-flash`** (fallback: `gemini-3.5-flash-lite` → `gemma-4-31b-it`) for stronger code generation and `SEARCH/REPLACE` diff fidelity.
4. **Stage 3/4 Escalation (`CoderAgent` attempt 3):** **`gemini-3.7-flash`** (fallback: `gemini-3.6-flash` → `gemma-4-31b-it`) — invoked *only* when two `gemini-3.5-flash` attempts fail `pytest`, concentrating our strongest verified free-tier Gemini model on genuine test-fix escalations.
5. **Stage 5 (`DeliveryAgent`):** **GitHub Models (`openai/gpt-4o-mini`)** via `https://models.github.ai/inference/chat/completions` authenticated with `${{ secrets.GITHUB_TOKEN }}` (`permissions: models: read`), saving Gemini quota on structured commit/PR summarization.
6. **Stage 6 (`ReviewerAgent`):** **GitHub Models (`openai/gpt-4o`, fallback `meta/llama-3.3-70b-instruct`)** via `GITHUB_TOKEN` (`models: read`). This consumes **zero Gemini quota** and provides true **cross-provider, cross-model reviewer independence** (Gemini builds, OpenAI/Meta reviews).

We rejected `gemini-4-*` (0 free-tier quota), `gemini-3.8-flash` (live `503` demand spikes), deprecated `gemini-2.5-*` (December 2026 rerouting), paid direct-billed providers (violate our \$0 cap), and desktop/local Ollama on a self-hosted runner (unacceptable security risk on a public fork and breaks ephemeral VM sandboxing).

## Consequences
Positive consequences include a guaranteed \$0 cost cap across both providers, verified live availability with graceful `429`/`503` fallback chains so transient spikes do not abort CI runs, ~35–40% fewer Gemini calls by offloading Stages 5–6 to GitHub Models, and genuine cross-provider diversity for independent PR review.

Negative consequences include maintaining two thin client adapters (`google-genai` and OpenAI-compatible GitHub Models REST) in `llm.py` and accepting Google AI Studio's free-tier data-use terms (safe because TinyDB is a public MIT-licensed repository with no private data or secrets).

Neutral consequences include logging provider, exact model ID (including any fallback used), and token usage (`prompt_tokens`, `output_tokens`, `total_tokens`) for every call into `usage.json`.
